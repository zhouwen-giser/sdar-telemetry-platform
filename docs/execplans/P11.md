# P11 ExecPlan — SDAR v1.4.1 Evidence v1 integration

## Goal

Integrate the current SDAR development branch with Telemetry Platform `main` through the frozen
`sdar.evidence/v1` export contract. The receiver must durably acknowledge only contiguous Evidence
sequences, preserve every recognized record losslessly, project compatible facts into the deployed
ClickHouse at `192.168.1.7`, and expose source-to-query traceability.

## Discoveries

- The current gateway accepts a legacy `schemaVersion/sourceType/batchId` contract and returns a
  legacy multi-field ACK, so a valid Runtime Evidence v1 delivery cannot complete.
- Gateway duplicate state is process-local and therefore is not an authority after restart.
- Current projection targets and rows do not match the vendor DDL; several target tables do not
  exist and specialized rows omit required columns or use incompatible types.
- `configFromEnv` ignores the inline ClickHouse password variables present in the operator's
  `.env`.
- The original `npm run verify` passes TypeScript/build/tests but its static check rejects the
  repository's installed `node_modules` directory.

## Decisions

- Producer contract wins. Legacy v1.3 relay support remains explicitly compatibility-only.
- The WAL stores the validated Evidence v1 batch and export identity before ACK. Durable WAL
  recovery, rather than an in-memory cache, is the duplicate authority.
- All 100 record types land in a lossless Evidence v1 canonical table. A specialized mapper is
  enabled only when the frozen producer fields can populate the deployed DDL without fabrication.
- Shared ClickHouse changes, if needed, are additive and idempotent only. No destructive command or
  migration is permitted.
- Credentials are never copied into tracked files, logs or reports.

## Validation

Commands, exit codes, request metadata, sequence ranges, hashes, WAL offsets, ClickHouse counts and
query samples are recorded under `reports/sdar-integration/evidence/`. A passing label is not used
without a corresponding real execution artifact.

## Rollback

Code changes are reverted by commit/file scope. WAL test data uses a unique integration run
identity. ClickHouse test rows are never deleted from shared history; the run identity makes them
independently queryable. Additive migrations include rollback notes but are not destructively rolled
back on the shared instance.
